# 功能規格：ESP32 積木包

**Feature Branch**: `claude/project-thread-zeku61`\
**Created**: 2026-10-22\
**Status**: 草稿\
**Input**: 讓老師用程式碼模板把新硬體或函式庫包成「積木包」，匯入專案後學生可在工具箱使用；第一版只支援 ESP32 DevKit。用內建積木組合新積木由既有「函式」功能負責，不在本功能範圍。取代未實作的 `046-custom-block-json` 規格。

## 使用情境與驗收

### 使用情境一：匯入積木包並使用（P1）

老師拿到一個積木包檔（例如超音波感測器），在 ESP32 DevKit 專案中匯入。工具箱出現以積木包名稱命名的分類，學生把積木拖進主程式，產生的程式碼包含積木包提供的標頭檔、全域宣告、初始化與每個積木的程式碼，並可上傳執行。

**獨立驗收**：匯入一個只含一個「讀取距離」積木的積木包，放進主程式後產生的程式可編譯上傳，序列埠讀到距離值。

1. **假設** 專案板子為 ESP32 DevKit，**當** 匯入合法積木包，**則**工具箱出現該積木包分類並列出全部積木。
2. **假設** 主程式使用同一積木包的多個積木，**當** 產生程式碼，**則**標頭檔、全域宣告與初始化各只出現一次。
3. **假設** 積木有數字、文字、下拉、腳位、值輸入或內層語句，**當** 產生程式碼，**則**每個輸入都以使用者設定的值取代模板中對應位置；文字值正確跳脫。
4. **假設** 匯入後儲存並重新開啟專案，**當** 編輯器載入，**則**積木包分類與工作區中的積木都完整還原。

### 使用情境二：專案分享後積木不會壞（P1）

學生把含有積木包積木的專案資料夾交給老師或同學，對方在另一台電腦開啟，不需要另外取得積木包檔。

**獨立驗收**：在 A 電腦匯入積木包並使用，複製整個專案到沒有該積木包檔的 B 電腦開啟，積木正常顯示並可產生相同程式碼。

1. **假設** 專案已使用積木包，**當** 在沒有原始積木包檔的環境開啟，**則**積木包分類與積木照常可用。
2. **假設** 外部工具或 AI 依專案 Skill 修改 `blockly/main.json` 並使用積木包積木，**當** 編輯器驗證該檔，**則**合法使用通過驗證，不因為是自訂積木而被拒絕。

### 使用情境三：板子不支援或定義遺失時保護工作區（P1）

學生把含有積木包積木的專案切換到其他板子，或積木包定義被移除。工作區結構不被破壞，也不產生編譯不過的程式。

1. **假設** 工作區有積木包積木，**當** 切換到 ESP32 DevKit 以外的板子，**則**工具箱不顯示積木包分類，既有積木保留並顯示「此板子不支援」警告，程式碼只產生說明註解。
2. **假設** 同一工作區，**當** 切換回 ESP32 DevKit，**則**警告消失且程式碼恢復。
3. **假設** 工作區有積木包積木，**當** 專案中的積木包定義被移除或損壞，**則**這些積木換成形狀相同的警告佔位積木，顯示原積木名稱，不產生程式碼，其他積木的位置與連接不變。
4. **假設** 已出現佔位積木，**當** 重新匯入同一積木包，**則**佔位積木還原為原積木，原本的輸入值與連接都保留。

### 使用情境四：老師製作與檢查積木包（P2）

老師（或由專案 Skill 協助的 AI）撰寫積木包檔，在編輯時取得欄位提示與錯誤標示，並可在匯入前預覽積木外觀與產生的程式碼。

1. **假設** 老師編輯積木包檔，**當** 輸入欄位，**則**編輯器提供合法欄位補全與錯誤標示。
2. **假設** 積木包有格式錯誤，**當** 匯入或預覽，**則**拒絕匯入並以使用者語系說明是哪個積木、哪個欄位有什麼問題。
3. **假設** 積木包合法，**當** 執行預覽，**則**看到每個積木的外觀與以預設值產生的程式碼。
4. **假設** 使用者要求專案 Skill「把某硬體做成 ESP32 積木包」，**當** AI 依 Skill 產生積木包，**則**該檔可通過驗證並匯入。

### 使用情境五：更新與移除積木包（P2）

1. **假設** 專案已匯入某積木包，**當** 匯入同一積木包的新版本，**則**顯示版本變更並在確認後更新；工作區中仍存在的積木保留設定。
2. **假設** 新版本移除了工作區正在使用的積木，**當** 更新完成，**則**這些積木成為佔位積木並提示使用者。
3. **假設** 工作區仍使用某積木包的積木，**當** 使用者要移除該積木包，**則**先說明會有多少積木成為佔位積木並要求確認。

### 邊界情況

- 積木包只支援 ESP32 DevKit；聲明其他板子的積木包被拒絕匯入，並說明第一版限制。
- 積木 type 一律加上積木包前綴，不得與內建積木或其他積木包衝突；同一積木包 id 只能存在一份。
- 腳位輸入使用 ESP32 DevKit 既有腳位清單；標為輸出用途時排除只能輸入的 GPIO34 到 39；類比輸入只列不與 Wi-Fi 衝突的 ADC1 腳位。
- 模板引用不存在的輸入名稱時拒絕匯入，而不是產生殘留佔位文字。
- 積木包的語句積木放在主程式或函式外時，比照內建積木顯示孤立警告且不產生程式碼。
- 積木包含 PlatformIO 函式庫依賴時，匯入前列出將下載的函式庫並需使用者確認；不信任的工作區不得匯入此類積木包。
- 積木包的全域宣告或初始化使用與工作區其他積木相同的腳位時，顯示衝突警告。
- 積木上的文字可提供多語系；目前語系缺字時依序退回英文、積木包預設語言。

## 需求

### 功能需求

- **FR-001**：使用者可在 ESP32 DevKit 專案匯入積木包檔；匯入後積木包分類出現在工具箱，並在不重新開啟編輯器的情況下可用。
- **FR-002**：積木包定義完整保存於專案的工作區檔案內，專案在沒有原始積木包檔的環境開啟仍可使用；不改變既有工作區欄位的意義。
- **FR-003**：積木包描述 id、版本、作者、分類名稱與顏色、積木清單，以及每個積木的標籤、形狀（執行一件事或回傳值）、輸入與 ESP32 DevKit 程式碼模板；模板可提供標頭檔、全域宣告、初始化與函式庫依賴。
- **FR-004**：輸入類型支援值輸入、數字、文字、下拉選單、腳位與內層語句；產生程式碼時以輸入值取代模板對應位置，不執行積木包中的任何指令碼。
- **FR-005**：同一積木包的標頭檔、全域宣告、初始化與函式庫依賴在一份程式中各只產生一次。
- **FR-006**：匯入與預覽時驗證積木包；格式錯誤、未支援的板子、重複 id、與內建積木衝突、模板引用不存在的輸入都拒絕匯入，並以使用者語系指出位置與原因。
- **FR-007**：含函式庫依賴的積木包，匯入前列出依賴並取得使用者確認；不信任的工作區不得匯入；依賴只接受 PlatformIO 函式庫名稱加版本，不接受任意網址。
- **FR-008**：非 ESP32 DevKit 板子不顯示積木包分類；工作區既有積木包積木保留、顯示板型警告且只產生註解。
- **FR-009**：積木包定義遺失或損壞時，工作區中的積木換成形狀相同的佔位積木並保留完整原始內容；定義恢復後自動還原。
- **FR-010**：積木包積木遵守既有孤立積木保護：工作區頂層忽略、產生程式時檢查所在位置、編輯時顯示警告。
- **FR-011**：外部編輯工作區檔案時的驗證把專案中積木包的積木視為合法積木並檢查其連接與欄位。
- **FR-012**：專案 Skill 說明積木包格式與使用方式，讓 AI 能產生可通過驗證的積木包並在工作區中正確使用其積木。
- **FR-013**：提供積木包檔的欄位提示與錯誤標示，以及顯示積木外觀與產生程式碼的預覽。
- **FR-014**：使用者可更新與移除已匯入的積木包；會讓工作區積木變成佔位積木的操作需先說明影響並確認。
- **FR-015**：新增的編輯器介面文字、警告與錯誤訊息支援 15 個語系；積木上的作者文字可選擇提供多語系。

### 主要實體

- **積木包（Block Pack）**：作者提供的檔案，含身分、版本、分類資訊、積木清單與 ESP32 DevKit 模板。
- **專案積木包快照**：匯入後存在專案工作區檔中的積木包完整副本，是載入與產生程式碼的唯一依據。
- **積木包積木**：工作區中的實例，型別帶有積木包前綴。
- **佔位積木**：定義缺失時替代的積木，保留原型別、形狀與完整原始內容。

## 成功標準

- **SC-001**：老師匯入一個合法積木包後 2 秒內，學生可在工具箱找到並拖用其積木。
- **SC-002**：使用積木包的專案複製到另一台沒有積木包檔的電腦，開啟後 100% 的積木包積木正常顯示且產生相同程式碼。
- **SC-003**：參考範例積木包（至少涵蓋值輸入、腳位、內層語句、函式庫依賴各一）產生的程式在 ESP32 DevKit 可編譯通過。
- **SC-004**：切換板子、移除或重新匯入積木包時，非積木包積木的位置與連接 0 變動；重新匯入後佔位積木 100% 還原。
- **SC-005**：每一類驗證錯誤都有指出積木與欄位的訊息，且在 15 個語系都有翻譯。

## 假設

- 第一版只支援 ESP32 DevKit；Super Mini（ESP32-C3）、Uno 系列、CyberBrick 與 TXT 依序於後續版本評估。
- 允許函式庫依賴，但需工作區信任與匯入確認（設計文件預設，Ray 可再調整）。
- 工具箱分類名稱直接使用積木包提供的名稱。
- 第一版不提供圖形化積木包編輯器，也不提供 PlatformIO 函式庫搜尋；作者以欄位提示、預覽與專案 Skill 製作。
- 積木包模板的程式正確性由作者負責；系統只驗證格式與引用，並透過範例與預覽協助。
- 舊分支 `046-custom-block-json` 保留不動，只作參考。
