# 功能規格：Blockly 13 現代化升級

**功能分支**：`065-blockly-v13-modernization`

**建立日期**：2026-08-09

**狀態**：草稿

**輸入**：將 Singular Blockly 升級至 Blockly 13.2.1，保留品牌化介面並採用新版視覺與互動，完整翻新過時整合方式，維持舊工作區相容，並完成十五語系、鍵盤及螢幕閱讀器驗收。

## 使用者情境與測試 *(必填)*

### 使用者故事 1：既有專案可無痛延續（優先級：P1）

身為既有 Singular Blockly 使用者，我希望升級擴充套件後仍能開啟、編輯、儲存及執行原有工作區，無須手動重建積木或修復專案。

**優先原因**：任何資料遺失、積木結構變更或程式碼輸出退化都會直接阻止升級，是本功能最核心的相容性要求。

**獨立測試**：使用涵蓋 Arduino、CyberBrick MicroPython、TXT Controller、變數、函式、mutator、shadow 與鎖定狀態的既有工作區集合，完成載入、儲存、重開及程式碼輸出比對。

**驗收情境**：

1. **假設**使用者有升級前建立的 JSON 工作區，**當**升級後開啟並重新儲存，**則**所有積木、連線、欄位、變數、函式、位置與動態狀態均完整保留。
2. **假設**使用者開啟舊版 XML 備份，**當**系統匯入備份，**則**可在不修改來源檔的情況下呈現等價工作區，後續能以現行格式儲存。
3. **假設**工作區包含三種支援的程式產生流程，**當**產生程式碼，**則**輸出行為與升級前一致，除非差異已被規格明確列為修正。
4. **假設**工作區為空或資料無效，**當**系統嘗試載入或儲存，**則**既有空狀態保護仍生效，且不會以空內容覆蓋有效資料。

---

### 使用者故事 2：使用新版且一致的積木介面（優先級：P2）

身為學生或教師，我希望編輯與預覽畫面採用新版 Blockly 視覺與操作回饋，同時延續 Singular Blockly 熟悉的明暗品牌配色。

**優先原因**：新版 renderer、控制圖示、焦點與輸入回饋是本次升級的主要可見價值，也必須在不犧牲品牌辨識度下保持一致。

**獨立測試**：分別在編輯與唯讀預覽模式檢查積木、工具箱、flyout、縮放控制、垃圾桶、欄位、搜尋高亮、明暗主題及高對比模式。

**驗收情境**：

1. **假設**使用者開啟編輯器，**當**載入任一支援開發板工具箱，**則**工作區使用新版積木外觀並維持 Singular 品牌配色。
2. **假設**使用者切換明暗主題或 VS Code 高對比模式，**當**工作區重新呈現，**則**積木、文字、焦點框、無效輸入與控制元件皆保持清晰可辨。
3. **假設**環境無法連線至外部網站，**當**開啟編輯或預覽畫面，**則**必要圖示、媒體與互動回饋仍可正常使用。
4. **假設**使用者使用唯讀預覽，**當**平移或縮放工作區，**則**外觀與編輯器一致且不會意外修改內容。

---

### 使用者故事 3：以鍵盤與輔助科技完成主要操作（優先級：P3）

身為依賴鍵盤、螢幕閱讀器或高對比顯示的使用者，我希望能理解工作區狀態並完成選擇、建立、移動、編輯與刪除積木等主要流程。

**優先原因**：Blockly 13 將鍵盤導覽與螢幕閱讀器支援列為預設能力；專案客製快捷鍵與介面不得削弱這些能力。

**獨立測試**：不使用滑鼠，搭配 macOS VoiceOver 完成從工具箱選取積木、放入工作區、編輯欄位、移動與刪除積木、操作變數及 mutator 的完整流程。

**驗收情境**：

1. **假設**工作區已取得鍵盤焦點，**當**使用者依序巡覽工具箱、flyout、積木、欄位及控制元件，**則**焦點順序、視覺指示與朗讀內容皆可理解。
2. **假設**AI 積木建議未啟用，**當**使用者按下 Tab、Escape 或其他 Blockly 預設鍵，**則**專案快捷鍵不會攔截原生導覽。
3. **假設**AI 積木建議已啟用，**當**使用者接受、取消或切換建議，**則**操作只在建議情境中生效，結束後焦點可繼續正常導覽。
4. **假設**使用者開啟變數、函式或 mutator 介面，**當**使用鍵盤及螢幕閱讀器操作，**則**名稱、目前值、可用動作與結果均有可理解的回饋。

---

### 使用者故事 4：切換語言後完整一致（優先級：P4）

身為使用任一支援語言的教師或學生，我希望切換介面語言後，Blockly 核心操作與 Singular Blockly 客製內容立即使用同一語言，不需重啟擴充套件。

**優先原因**：新版加入大量鍵盤與輔助科技訊息；若核心與專案翻譯載入不同步，會造成混合語言並降低可理解性。

**獨立測試**：逐一驗證十五種支援語言，並以語言 A → 語言 B → 語言 A 的方式檢查可見文字、工具箱、積木欄位、提示與輔助科技訊息。

**驗收情境**：

1. **假設**工作區已有未儲存內容，**當**使用者切換語言，**則**內容與選定開發板保持不變，介面使用新語言重新呈現。
2. **假設**使用者連續切換不同語言，**當**螢幕閱讀器朗讀工作區與快捷鍵提示，**則**不會殘留前一語言的核心訊息。
3. **假設**某語言的專案訊息覆寫 Blockly 核心文字，**當**語言完成載入，**則**專案覆寫具有一致且可預期的優先順序。

### 邊界情況

- 工作區含有缺少定義、孤立、停用、摺疊或實驗性積木時，升級後仍須安全呈現既有警告與程式產生保護。
- 工作區含大量積木、深層巢狀結構或多個 mutator 時，不得因新版呈現造成明顯無回應或狀態遺失。
- 切換語言、主題或開發板期間收到檔案監看更新時，不得將中間空狀態寫回專案。
- 變數重新命名或刪除時，所有引用必須同步更新或依使用者確認處理，不得留下無效引用。
- 輸入法正在組字時，Enter、Escape、Tab 與快捷鍵不得提前提交、取消或移動焦點。
- 外部網路、官方媒體主機或語言服務不可用時，編輯器及預覽仍須使用套件內資源完成啟動。
- 工作區資料毀損或不符合支援格式時，系統須保留原資料並提供可理解的錯誤，不得靜默覆寫。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系統必須將 Blockly 核心升級至 13.2.1，並使用與其相容的官方 Modern theme 版本。
- **FR-002**：系統必須在編輯與唯讀預覽模式採用 Thrasos 外觀，同時保留 Singular Blockly 明暗品牌主題。
- **FR-003**：系統必須將所有新版所需的圖示、音效及媒體資源隨擴充套件提供，不得依賴外部網路才能完成主要操作。
- **FR-004**：系統必須完整載入、編輯及儲存升級前建立的 JSON 工作區，且不得遺失積木狀態或使用者資料。
- **FR-005**：系統必須保留舊版 XML 備份匯入能力，但新建立與重新儲存的工作區以現行格式為主。
- **FR-006**：系統必須確保 Arduino、MicroPython 與 TXT Controller 的代表性工作區在升級後產生等價程式行為。
- **FR-007**：系統必須維持所有動態積木、函式參數、變數、shadow、鎖定狀態及自訂 mutator 的儲存與還原能力。
- **FR-008**：系統必須淘汰目標版本已移除、已過時或未公開的整合介面，並以目標版本支援的公開能力取代。
- **FR-009**：系統不得透過修改 Blockly 核心類別的全域行為來實作變數對話框、IME、工作區整理保存或實驗積木標記。
- **FR-010**：變數新增、重新命名及刪除必須沿用 VS Code 原生互動體驗、開發板別名稱驗證與 Blockly 正常事件語意。
- **FR-011**：系統必須保留 Blockly 13 預設的鍵盤導覽與螢幕閱讀器能力，且專案快捷鍵只能在其功能情境成立時攔截按鍵。
- **FR-012**：所有可互動的積木、欄位、輸入、圖示、工具箱項目、flyout 項目與對話流程必須提供可辨識的焦點與可理解的輔助科技名稱。
- **FR-013**：系統必須支援 Singular Blockly 現有十五種語言，並在執行階段切換語言時同步更新核心與客製訊息。
- **FR-014**：語言切換必須保留工作區、開發板、主題及尚未遺失的編輯狀態，不得混用切換前後的核心輔助科技訊息。
- **FR-015**：系統必須維持空工作區保護、檔案監看載入保護與錯誤資料保護，避免升級或重新呈現期間覆蓋有效專案。
- **FR-016**：搜尋高亮、實驗積木標記、工具箱篩選與整理工作區保存必須在新版外觀與焦點模型下維持原有使用者結果。
- **FR-017**：擴充套件封裝後必須包含執行 Blockly 13 所需的核心、主題、語言及媒體資源。
- **FR-018**：若載入、重新呈現或語言切換失敗，系統必須保留最近有效的工作區資料並向使用者提供可理解的錯誤訊息。

### 關鍵實體

- **工作區狀態**：使用者的積木、變數、函式、連線、位置、欄位、動態狀態與相關設定集合。
- **介面語言包**：由 Blockly 核心訊息與 Singular Blockly 客製訊息組成，依支援語言載入並具有明確覆寫順序。
- **工作區呈現設定**：包含品牌主題、顯示模式、開發板、語言及無障礙焦點狀態。
- **對話請求**：需要 Extension Host 顯示輸入或確認介面的非同步操作，具有唯一識別、提示內容與結果。

### 範圍界線

- 本功能不重做編輯器外層工具列、上傳面板、備份管理或硬體操作流程。
- 本功能不新增開發板、積木類型、程式語言或一般使用者功能。
- 本功能不移除舊 XML 備份匯入能力，也不要求使用者批次轉換既有專案。
- 本功能不進行正式無障礙法規認證；範圍為鍵盤、VoiceOver、高對比與專案主要流程的功能驗收。
- 本功能不改變工作區檔案的對外資料架構，除非為保留既有狀態所需的向後相容補強。

## 成功標準 *(必填)*

### 可衡量成果

- **SC-001**：相容性測試集合中的既有 JSON 與 XML 工作區達到 100% 可載入，且經儲存與重開後沒有狀態遺失。
- **SC-002**：Arduino、MicroPython 與 TXT Controller 的代表性程式輸出測試達到 100% 通過，未核准的行為差異為零。
- **SC-003**：十五種支援語言均能完成 A → B → A 切換，畫面與輔助科技訊息的前一語言殘留為零。
- **SC-004**：使用者僅以鍵盤即可完成工具箱巡覽、建立積木、編輯欄位、移動、刪除、變數與 mutator 等主要流程，阻斷性問題為零。
- **SC-005**：macOS VoiceOver 驗收涵蓋所有主要流程，嚴重或高優先級的名稱、狀態、焦點與操作宣告問題為零。
- **SC-006**：明亮、深色及 VS Code 高對比模式下，所有主要文字、焦點指示、無效輸入與控制元件均可辨識，阻斷性視覺問題為零。
- **SC-007**：在封鎖外部網路的環境中，編輯與預覽工作區仍可完成啟動、顯示及主要互動，外部資源請求需求為零。
- **SC-008**：自動相容性檢查對已移除、過時及未公開整合方式的未核准使用回報為零。
- **SC-009**：含 500 個代表性積木的工作區，其載入與主要互動時間相較升級前基準不得惡化超過 10%。
- **SC-010**：專案編譯、靜態檢查、單元測試、整合測試、國際化驗證及正式封裝全部通過。

## 假設

- 本次 SDD 期間以 Blockly 13.2.1 與相容的 Modern theme 版本作為固定驗收基準，不追逐後續新發布版本。
- 專案既有 Node.js 22.16.0 以上與 VS Code 1.105.0 以上基準保持不變。
- 主要工作區資料已使用 JSON；XML 僅作為舊備份與相容性匯入來源。
- 既有 Singular Blockly 明暗配色、十五語系清單及開發板行為是相容性基準。
- 無障礙驗收以 macOS VoiceOver、純鍵盤與 VS Code 高對比模式為人工基準，並以可自動化的契約測試補強。
- 升級不得要求使用者連線至 Blockly 官方網站，亦不得要求重建現有工作區。

## 相依條件

- Blockly 13.2.1 與其相容的官方 Modern theme 套件可被正式封裝。
- 現有 JSON 工作區、舊 XML 備份、三種程式產生流程及十五語系測試資料可作為回歸基準。
- VS Code WebView 能載入擴充套件內封裝的核心、主題、語言與媒體資源。
