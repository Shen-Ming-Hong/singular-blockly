# Feature Specification: 提供回饋與進度追蹤

**Feature Branch**: `codex/070-user-feedback`

**Created**: 2026-08-19

**Status**: Draft

**Input**: User description: "新增讓沒有 GitHub 經驗的使用者可以直接在 Singular Blockly 提供問題、功能建議或其他回饋；由使用者確認後送出必要且最小化的環境資訊，可選擇附加近期事件或一張截圖，並能追蹤、補充及刪除自己的回饋。維護者需能私下分流並在取得核准後建立匿名公開開發紀錄；整體設計必須符合 VS Code Marketplace 與 Open VSX 的隱私、安全及上架要求。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 不需 GitHub 即可提供回饋 (Priority: P1)

使用者可從 Blockly 編輯器內具獨立顏色、圖示與可存取名稱的產品入口或命令選單開啟「提供回饋」，選擇問題回報、功能建議、使用疑問或其他回饋，填寫容易理解的表單，先檢視即將傳送的資訊，再明確確認送出。整個流程不要求使用者擁有或理解 GitHub 帳號。

**Why this priority**: 這是功能的核心價值；若不能讓一般使用者低摩擦且知情地送出回饋，其餘追蹤與分流能力都無法產生價值。

**Independent Test**: 以全新安裝、沒有任何 GitHub 登入狀態的環境完成一筆回饋，確認送出前可看到完整資料摘要，送出後取得可識別的回饋編號。

**Acceptance Scenarios**:

1. **Given** 使用者正在 Singular Blockly 編輯器中且工具列已展開，**When** 點選具有本地化提示與可存取名稱的圓形「提供回饋」圖示按鈕，**Then** 系統在 VS Code 內開啟可完成填寫與送出的表單，且入口位於產品自己的工具列、不與其他擴充套件的編輯器標題按鈕混在一起。
2. **Given** 使用者收合 Blockly 工具列，**When** 查看仍可使用的操作，**Then** 只保留備份、上傳、Monitor 與最右側的展開按鈕；重新展開後其他可用操作依原功能狀態恢復顯示。
3. **Given** 使用者不熟悉 GitHub，**When** 從命令選單執行「Singular Blockly: 提供回饋」，**Then** 流程不要求建立帳號、登入第三方開發平台或離開 VS Code 才能送出。
4. **Given** 使用者已填寫必要欄位，**When** 準備送出，**Then** 系統先列出使用者文字、附件與所有將傳送的環境欄位，並要求明確確認。
5. **Given** 使用者未勾選近期事件，**When** 送出回饋，**Then** 回饋不包含近期事件或原始紀錄。
6. **Given** 使用者關閉基本環境資訊，**When** 送出回饋，**Then** 除回饋內容與完成傳送所必要的安全資訊外，不傳送該批環境資訊，且介面提醒可能降低診斷效率但不阻擋送出。
7. **Given** 網路暫時失敗或服務拒絕請求，**When** 使用者送出，**Then** 系統保留尚未送出的表單內容、顯示可理解的原因與安全重試方式，不宣稱回饋已建立。

### User Story 2 - 自主控制診斷資料與截圖 (Priority: P1)

使用者能理解並控制診斷資料：基本環境資訊預設開啟、近期結構化事件預設關閉、截圖必須由使用者主動附加。系統只收集已列出的最小必要欄位，主動阻擋或移除敏感內容。

**Why this priority**: 回饋功能會把本機資訊傳送至外部服務；資料最小化、透明度與明確同意是信任、安全及上架合規的必要條件。

**Independent Test**: 分別以預設、全部關閉及主動附加事件/截圖三種組合檢查送出預覽與實際收到的內容，確認只有使用者可見且核准的資料被傳送。

**Acceptance Scenarios**:

1. **Given** 使用者第一次開啟表單，**When** 查看診斷資料選項，**Then** 基本環境資訊為開啟、近期結構化事件為關閉，且每組資訊都附有用途與內容說明。
2. **Given** 使用者選擇加入近期事件，**When** 預覽內容，**Then** 只看見有限筆數、具固定欄位的階段與代碼，不包含原始錯誤文字、完整紀錄或使用者內容。
3. **Given** 使用者主動加入一張截圖，**When** 系統處理附件，**Then** 先移除中繼資料、限制尺寸及容量，並讓使用者在送出前預覽或移除。
4. **Given** 環境資料或截圖可能包含路徑、憑證、網路識別資訊或其他禁收內容，**When** 系統建立傳送內容，**Then** 敏感資料會被阻擋或遮蔽，且使用者收到清楚提示。
5. **Given** 使用者只開啟表單但沒有送出，**When** 關閉表單，**Then** 系統不對外傳送回饋、診斷資料或附件。

### User Story 3 - 查看、補充與刪除自己的回饋 (Priority: P2)

送出者不需建立帳號即可在擴充套件與專屬網頁查看自己送出的回饋、公開狀態、維護者公開回覆與待補資訊；可補充純文字說明，也可刪除單筆或全部回饋。

**Why this priority**: 回報不是一次性投遞；可追蹤與自主刪除能降低不確定感，也落實資料主體控制權。

**Independent Test**: 在一個新使用者環境送出兩筆回饋，於 VS Code 與備援網頁查看相同狀態，補充其中一筆後刪除單筆，再刪除其餘全部資料。

**Acceptance Scenarios**:

1. **Given** 回饋已成功建立，**When** 使用者開啟「我的回饋」，**Then** 只看見由目前回報者識別所建立的回饋，不會看見其他人的資料。
2. **Given** 使用者取得送出後提供的備援連結，**When** 在瀏覽器開啟，**Then** 可建立短期安全工作階段並查看同一批個人回饋，頁面與網址不洩漏可重用的密鑰。
3. **Given** 回饋狀態為需要資訊，**When** 使用者送出補充文字，**Then** 維護者可看見該補充且使用者可在自己的時間軸中確認已送達。
4. **Given** 使用者刪除單筆回饋，**When** 刪除完成，**Then** 回饋本文、訊息、附件與可連結身分的資料不再可由產品介面或維護介面取回。
5. **Given** 使用者選擇刪除全部回饋，**When** 再次確認，**Then** 所有仍與該回報者相連的回饋資料皆被刪除，且本機保存的回報者憑證失效。
6. **Given** 已有經使用者核准後建立的匿名公開開發紀錄，**When** 原回報者刪除回饋，**Then** 私密資料與對應關係被移除，但不含個人內容的公開開發紀錄可保留，且此例外已在送出與刪除說明中揭露。

### User Story 4 - 維護者安全分流與公開溝通 (Priority: P2)

維護者能在私密工作區查看所有未審回饋、尋找重複項目、取得自動分類建議並作最終決定。內部討論預設不會公開給回報者；只有明確的公開回覆或狀態動作才會同步。需要進入產品開發的回饋，必須經專案負責人核准後才能產生去識別化的公開開發紀錄。

**Why this priority**: 沒有一致、安全且可稽核的處理流程，回饋容易遺漏，私密討論也可能誤傳給使用者。

**Independent Test**: 建立多種回饋及一組疑似重複回饋，執行批次分流，驗證建議標籤、最終決定、公開回覆與匿名公開開發紀錄都遵守核准邊界。

**Acceptance Scenarios**:

1. **Given** 存在多頁未審回饋，**When** 維護者執行分流，**Then** 系統會處理所有頁面、搜尋可能的重複項目，並只產生可審核的分類與處置建議。
2. **Given** 回饋本文包含看似命令或要求洩漏資料的文字，**When** 自動分流，**Then** 內容只被視為不可信資料，不會因此執行命令、讀取額外資料或改變核准流程。
3. **Given** 維護者在私密工作區留言，**When** 未使用明確公開動作，**Then** 留言不會出現在回報者時間軸。
4. **Given** 維護者將回饋判定為不採取行動，**When** 儲存決定，**Then** 必須同時選擇結案原因並提供尊重、可理解的對外說明。
5. **Given** 維護者或自動分流建議建立公開開發紀錄，**When** 尚未取得專案負責人明確核准，**Then** 系統不會建立或發布該紀錄。
6. **Given** 已核准建立公開開發紀錄，**When** 系統產生摘要，**Then** 摘要不包含回報者識別、原始附件、機器資訊、私密討論或可反向連結至私密回饋的識別碼。

### User Story 5 - 符合擴充套件上架資訊揭露 (Priority: P1)

安裝者與審查者在安裝前及送出前，都能清楚得知此功能使用的線上服務、資料類型、用途、處理者、保存與刪除方式；相關文件可從市集頁面、專案文件與服務頁面取得。

**Why this priority**: 缺少完整隱私揭露會讓原本合理的支援功能不符合市集政策，也會破壞使用者信任，因此是發布阻擋條件。

**Independent Test**: 以未安裝擴充套件的審查者角度，從市集資訊進入隱私與支援文件；再以已安裝使用者檢查送出與刪除前的揭露是否一致。

**Acceptance Scenarios**:

1. **Given** 使用者尚未安裝擴充套件，**When** 查看市集頁面，**Then** 可找到線上服務與資料使用摘要，以及可公開存取的隱私與支援文件連結。
2. **Given** 使用者準備送出回饋，**When** 查看確認頁，**Then** 可辨識收集項目、目的、外部處理者、保存政策、刪除方式及公開匿名摘要例外。
3. **Given** 產品面向學生或未成年使用者，**When** 相關使用者查看表單，**Then** 介面明確提醒不要輸入姓名、電子郵件或其他可識別個人資訊。
4. **Given** 擴充套件被打包上架，**When** 審查封裝內容，**Then** 不包含後端管理程式、服務秘密、私密金鑰或僅供維護者使用的設定。

### Edge Cases

- 同一送出動作因逾時而被重試時，不得建立重複回饋或重複訊息。
- 本機回報者憑證遺失、安全儲存被清除或使用者換機時，系統不得猜測或還原他人的回饋；介面需說明只有仍持有備援連結的使用者可重新建立存取。
- 備援連結外洩時，使用者刪除全部回饋或重設識別後，舊憑證與既有工作階段必須失效。
- 截圖超過限制、格式偽裝、解碼失敗或含不支援格式時，附件會被拒絕，但使用者仍可移除附件後送出純文字回饋。
- 回饋文字、標題、補充訊息或分類值超過限制時，系統必須在送出前提示，不可靜默截斷造成語意改變。
- 服務暫時無法同步至維護者工作區時，使用者已成功建立的回饋仍可查詢，系統稍後安全重試且不建立重複項目。
- 維護者工作區中的項目被手動刪除、改名或加入非預期狀態時，系統不得把私密內容轉為公開，也不得污染其他回饋。
- 外部事件被重送、順序顛倒或來源不在允許清單時，系統只接受通過驗證且尚未處理的事件。
- 回饋被判定為垃圾內容時，仍須遵守資料刪除與對外狀態規則；安全防濫用紀錄可按較短且已揭露的週期獨立保存。
- 受信任與不受信任工作區、無工作區、遠端工作區及受限模式下，回饋功能都不得讀取工作區內容來補足診斷資訊。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供 Blockly 編輯器產品工具列內具獨立顏色、回饋圖示、本地化 tooltip 與 ARIA 名稱的圓形入口，以及命令選單入口；兩者皆開啟同一個「提供回饋」流程，且不得只依賴容易與其他擴充套件混淆的通用編輯器標題列圖示。
- **FR-002**: 系統 MUST 支援「問題回報」、「功能建議」、「使用疑問」與「其他回饋」四種回饋種類。
- **FR-003**: 回饋表單 MUST 以非技術使用者可理解的語言說明必要欄位、資料用途、送出結果與後續追蹤方式，不得要求 GitHub 經驗或帳號。
- **FR-004**: 使用者 MUST 在送出前檢視完整傳送摘要並執行明確確認；僅開啟或填寫表單不得觸發任何對外傳輸。
- **FR-005**: 系統 MUST 將基本環境資訊設為預設開啟且可關閉，並將近期結構化事件設為預設關閉且需主動開啟。
- **FR-006**: 基本環境資訊 MUST 僅限：擴充套件版本、編輯器版本、作業系統家族與主版本、處理器架構、介面語系、標準化的本機或遠端類型、工作區類型與信任狀態、目前開發板、程式語言、相關工具版本或就緒狀態，以及最近一次穩定錯誤的階段與代碼；客戶端與服務端都 MUST 以版本／穩定代碼格式允許清單拒絕路徑、空白原文及憑證形狀的值。
- **FR-007**: 近期結構化事件 MUST 只包含有上限的時間、階段、事件代碼與結果，不得包含原始訊息、堆疊、完整紀錄或使用者內容。
- **FR-008**: 系統 MUST NOT 收集或傳送原始碼、工作區序列化資料、產生的程式碼、檔案或資料夾名稱、完整或部分路徑、機器或裝置識別碼、序列埠、Wi-Fi 資訊、IP 位址、環境變數、權杖、憑證、原始錯誤訊息或原始紀錄。
- **FR-009**: 系統 MUST 重用一致的隱私遮蔽規則處理所有既有與新增的問題回報入口，既有特定工具的回報流程 MUST 導向通用回饋表單。
- **FR-010**: 使用者 MAY 主動附加最多一張截圖；系統 MUST 在解碼前限制原始容量、header 可驗證尺寸與像素預算，再於本機移除中繼資料、重新編碼、限制最長邊為 1920 像素且限制檔案為 3 MiB，服務端 MUST 再次驗證格式、尺寸與容量；被新選擇或移除取代的非同步處理結果 MUST 被忽略。
- **FR-011**: 系統 MUST 在截圖送出前提供可視預覽與移除動作，並提醒使用者檢查畫面中的姓名、郵件、路徑、程式內容與其他私人資訊。
- **FR-012**: 回饋成功建立後，系統 MUST 回傳回饋編號、目前狀態與可保存的備援存取方式；本機安全儲存不得保存明文可驗證憑證於一般設定或工作區檔案。
- **FR-013**: 回報者識別 MUST 使用高強度、不含個人資訊的隨機秘密；服務端只能保存不可逆的驗證表示，備援網址不得把可重用秘密傳送給一般網路請求或第三方資源。
- **FR-014**: 備援存取 MUST 先交換為短期、安全、不可由前端程式讀取的工作階段，並在交換後從可見網址移除秘密。
- **FR-015**: 系統 MUST 提供「我的回饋」清單與明細，且只能顯示目前回報者自己的標題、描述、重現步驟、預期結果、允許清單式環境資訊、附件保存狀態、公開狀態、對外回覆與補充訊息；Extension 與備援入口的欄位語意 MUST 一致，分頁與明細 MUST 只接受目前 in-flight cursor 或最後一次選取的 feedback ID。
- **FR-016**: 回報者 MUST 能對自己的既有回饋補充純文字訊息；本文 MUST 在建立冪等 fingerprint、送出與成功回應驗證前使用同一 trim 正規化值，第一版不接受補充附件。Extension 與備援入口 MUST 依 feedback ID 在記憶體保留尚未明確成功的補充草稿；網路失敗、結果不確定或切換明細不得清除草稿，且已持久保存的冪等鍵 MUST 可與相同本文配對重試。只有服務端成功回應完成結構與本文驗證後才可清除對應草稿。
- **FR-017**: 回報者 MUST 能刪除單筆回饋或刪除全部回饋；刪除前需再次確認影響範圍。刪除全部回饋時，撤銷 reporter/session 與將每筆資料標為不可讀並建立持久 delete outbox MUST 在同一交易完成，排程須持續重試隱私刪除而不得永久 dead-letter。若已開始的建立請求因 reporter 被同步撤銷而失敗，客戶端 MUST NOT 在同一次操作自動建立新 reporter 並重送；只能保留表單並要求使用者再次明確送出。單筆刪除成功後 MUST 從清單移除該筆並同步重新整理清單；若使用者已切換至其他明細，不得清除或取代目前明細與其進行中狀態。
- **FR-018**: 刪除回饋 MUST 移除主要資料、訊息、附件與私密維護者副本中的原始內容。私密工作項目清除留言時只可在必要期間暫時解除鎖定，每個有界批次後 MUST 重新鎖定並在鎖定狀態確認留言為空，失敗路徑也 MUST 嘗試恢復鎖定；僅在已證明清空後才可留下不含內容的關閉墓碑。因 GitHub conversation lock 不阻止具寫入權限者留言，不含內容的 tombstone MUST 保留 private issue routing number；刪除中或刪除後若收到該 issue 的新留言 webhook，MUST 在 mapping 或 tombstone 仍可辨識時原子建立／更新 content-free tombstone 與新的持久 scrub outbox，再持續重試。若外部 Issue marker 搜尋或內容清除達安全上限而無法證明完整，MUST 保留刪除工作並 fail closed 重試，不得把未知結果當成不存在、先完成 D1 刪除或關閉墓碑。
- **FR-019**: 系統 MUST 明確揭露：服務提供者的安全稽核或備份可能依其政策短期保留不可即時刪除的副本。
- **FR-020**: 回饋資料 MUST 在回報者刪除前持續保存，不設自動到期；工作階段、防濫用與安全稽核資料 MUST 採較短、明確揭露且與回饋內容分離的保存週期。
- **FR-021**: 回饋 MUST 同時具有「處置決定」與「公開狀態」兩個獨立維度；處置決定為未審、採取行動、不採取行動，公開狀態為已收到、分流中、需要資訊、已規劃、進行中、已解決、已關閉。
- **FR-022**: 不採取行動的回饋 MUST 同時包含結案原因與尊重、可理解的公開說明；原因至少支援重複、非產品範圍、不支援、超出目前範圍、無法重現、資訊不足及垃圾內容。
- **FR-023**: 系統 MUST 支援回饋種類、影響區域、影響程度、自動建議、維護者最終決定、公開狀態及結案原因等分流欄位，且清楚區分自動建議與人工決定。
- **FR-024**: 維護者 MUST 能檢視所有未審回饋、跨頁取得完整清單、搜尋疑似重複項目，並取得可審查的種類、區域、影響與建議處置。
- **FR-025**: 回報者輸入 MUST 一律視為不可信資料；自動處理不得執行其中的命令、遵循其中的代理指示、擴張資料存取或繞過核准。
- **FR-026**: 維護者內部討論 MUST 預設保持私密；只有明確執行公開回覆、公開狀態或要求補充資訊的動作時，才可同步給回報者。
- **FR-027**: 將回饋轉成公開開發紀錄 MUST 先取得專案負責人明確核准，並只發布無法連回原回報者或私密項目的去識別化摘要；逐字片段檢查 MUST 涵蓋以空白分詞及中文、日文、韓文等無空白語系，GitHub mention 則須在行首、空白、括號與其他標點邊界一致拒絕。
- **FR-028**: 公開開發紀錄一旦建立 MAY 在原回饋刪除後保留，但 MUST 移除與私密回饋的關聯，且此例外須在核准與刪除流程中預先揭露。
- **FR-029**: 被採納且需要新增功能或跨領域變更的公開開發項目 MUST 重新走完整規格驅動開發流程，不得把回饋本文直接當作可執行計畫。
- **FR-030**: 所有建立、補充、刪除與外部事件處理 MUST 能安全重試而不產生重複結果，並驗證資料結構、欄位長度、允許值與總容量；使用者可見文字的長度 MUST 在 Webview、Extension Host、Worker 與 D1 一致以 Unicode code point 計算；結果不確定的補充訊息與單筆刪除 MUST 以不含本文的 digest／目標識別與冪等鍵跨 Webview 重開保存至明確成功或不可重試失敗，不同 digest／目標的未決操作 MUST 能同時存在而不互相覆寫；每個已驗證的私密維護者命令 MUST 產生 idempotent 短確認，確認失敗時同一 webhook delivery 只重試確認，不得重做 domain mutation。
- **FR-031**: 所有會改變資料的瀏覽器請求 MUST 防止跨站偽造與不受信任來源，所有外部事件 MUST 驗證來源真實性、允許的儲存庫及事件唯一性。
- **FR-032**: 系統 MUST 對送出、補充、登入交換與查詢實施合理的濫用限制，不得長期保存原始網路位址；必要的短期防濫用識別 MUST 無法直接還原原始位址，且同一 reporter 的 bearer 與所有 recovery sessions MUST 共用一個穩定主要限速鍵。
- **FR-033**: 維護者附件存取 MUST 經過獨立的維護者身分驗證與授權，附件不得形成公開或可猜測網址。
- **FR-034**: 使用者成功建立回饋後，即使維護者工作區暫時失敗仍 MUST 可查詢；系統 MUST 在背景可靠重試私密同步並避免重複。
- **FR-035**: 系統 MUST 提供繁體中文在內的全部 15 個既有語系，包含隱私權、支援與條款的完整服務頁本文；所有新增文案鍵、插值參數及 HTML 內容皆須通過語系一致性驗證，支援語系不得把完整政策本文強制回退成英文。
- **FR-036**: 市集頁面、專案文件與服務頁面 MUST 提供一致且可公開存取的隱私、支援及服務條款資訊，說明收集項目、目的、處理者、資料位置、保存、刪除、備份及匿名公開摘要政策。
- **FR-037**: 市集資訊 MUST 提供有效的專案首頁與支援入口，並在發布者後台設定隱私政策連結；缺少任一發布者無法由原始碼驗證的設定時，發布檢查 MUST 阻擋並要求人工確認。
- **FR-038**: 回饋功能 MUST 明確標示其為使用者主動啟動的支援資料傳送，而非遙測或分析；若未來加入遙測，MUST 另行遵守編輯器的全域遙測選擇與資料宣告機制。
- **FR-039**: 擴充套件封裝 MUST 排除服務端程式、管理工具、秘密、測試資料與部署設定，只包含執行回饋客戶端所需資產。
- **FR-040**: 回饋表單與我的回饋介面 MUST 使用受限內容安全政策，不載入遠端可執行程式，所有網路通訊由受控的擴充套件端點代理並驗證訊息來源與結構。
- **FR-041**: 系統 MUST 提供穩定、可稽核且不會洩漏敏感內容的安全事件記錄；產品紀錄不得輸出回報者秘密、工作階段、附件內容或完整回饋本文。
- **FR-042**: 功能發布前 MUST 通過單元、契約、整合、端對端、安全、語系與封裝檢查，並以人工情境驗證編輯器內表單、鍵盤操作、語意標籤、縮放及深淺色／高對比主題；本功能不以實際語音朗讀作為發布條件。
- **FR-043**: Blockly 產品工具列 MUST 提供最右側的收合／展開按鈕；尚無專案偏好時預設收合，之後以 VS Code 專案 `workspaceState` 保存使用者最後選擇，並在 Webview 重建或重新開啟該專案時恢復。收合時只能顯示開發板選擇、備份、上傳、Monitor 與收合／展開按鈕，展開時其他目前適用的操作恢復顯示，且所有圓形操作按鈕的水平間距 MUST 一致。按鈕 MUST 以本地化 tooltip、ARIA label 與 `aria-expanded` 表達目的和狀態，不得只靠顏色或箭頭方向；此偏好不得寫入 Blockly workspace 檔案或傳送到外部服務。

### Key Entities *(include if feature involves data)*

- **回報者（Reporter）**: 不含姓名或電子郵件的匿名擁有者；透過高強度秘密證明自己可讀取、補充或刪除所屬回饋。
- **回饋（Feedback）**: 使用者提供的種類、標題、描述、重現資訊、期望結果、環境選擇、公開狀態、處置決定與時間資訊。
- **診斷快照（Diagnostic Snapshot）**: 經允許清單與遮蔽規則產生的最小環境資料，以及使用者明確選擇時才加入的近期結構化事件。
- **附件（Attachment）**: 使用者主動加入、已淨化且受私密存取保護的單一截圖。
- **回饋訊息（Feedback Message）**: 回報者補充文字或維護者明確公開的回覆；與私密維護者討論分離。
- **分流評估（Triage Assessment）**: 自動分類建議、疑似重複項目與安全提示；不可取代維護者最終決定。
- **公開開發紀錄（Public Development Record）**: 經使用者核准、去識別化且切斷私密關聯的產品開發摘要。
- **安全工作階段（Secure Session）**: 由回報者秘密交換而來、範圍受限且可撤銷的短期存取狀態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的首次使用測試者能在沒有 GitHub 帳號或教學的情況下，於 3 分鐘內完成一筆有效回饋。
- **SC-002**: 100% 的送出測試都會在傳輸前顯示與實際傳送內容一致的摘要，且僅開啟或取消表單的測試不會產生任何對外資料傳輸。
- **SC-003**: 在預設設定下，100% 的測試回饋不含原始紀錄、原始錯誤、來源內容、工作區資料、路徑、憑證或可識別裝置的資料。
- **SC-004**: 在 100 組正常、惡意與偽裝附件測試中，所有超出格式或容量限制的附件都被拒絕，所有接受的附件都已移除中繼資料且不超過 3 MiB 與 1920 像素最長邊。
- **SC-005**: 95% 的正常回饋送出在 10 秒內得到明確成功或可重試結果；所有逾時重試測試均不產生重複回饋。
- **SC-006**: 回報者在擴充套件與備援網頁看到的公開狀態與訊息一致率為 100%，且任何跨回報者存取測試都無法讀取、修改或刪除他人資料。
- **SC-007**: 單筆與全部刪除測試皆在 60 秒內讓產品及維護介面無法取回私密內容，並保留符合揭露內容的最小墓碑或匿名公開紀錄。
- **SC-008**: 100% 的維護者內部留言不會在未明確公開時出現在回報者介面；100% 的公開開發紀錄都具專案負責人核准證據且不含禁止欄位。
- **SC-009**: 自動分流能完整處理至少 500 筆、跨 10 頁的未審回饋而不漏項，且所有建議都可由維護者逐項核准、修改或拒絕。
- **SC-010**: 100% 的提示注入測試都不會導致命令執行、額外資料讀取、秘密輸出、未授權公開回覆或未核准的公開開發紀錄。
- **SC-011**: 15 個支援語系皆無缺漏鍵、插值錯誤或無法顯示的主要流程文案；鍵盤可完成送出、查看及刪除核心流程，所有主要控制項皆具有可稽核的 HTML/ARIA 名稱與狀態。
- **SC-012**: 發布前檢查能確認市集頁面可到達隱私與支援文件、封裝不含服務端或秘密、所有合規揭露一致；任何一項缺失都會阻擋發布。
- **SC-013**: 在 15 個支援語系、鍵盤操作、深色／淺色／高對比主題與約 200% 縮放下，工具列收合時只保留指定常用操作且不發生水平內容遺失；展開後所有依目前開發板適用的操作皆可到達、圓形按鈕間距一致，收合狀態在 Webview 重建後正確恢復。

## Assumptions

- 第一版以使用者主動送出回饋為唯一觸發，不進行背景遙測、崩潰自動上傳或使用行為分析。
- 使用者可在有網路時完成送出與查看；離線草稿同步與背景通知不在第一版範圍。
- 回報者不提供姓名或電子郵件，維護者需要補充資訊時透過回饋時間軸往返。
- 第一版每筆回饋最多一張初始截圖，後續補充只接受文字。
- 回饋內容在使用者刪除前無自動到期；安全與防濫用資料採較短週期並於隱私文件列明。
- 私密維護者工作區僅供專案維護者使用，不是回報者身分系統，也不會向回報者暴露其內部網址或帳號概念。
- 回饋成為公開開發工作前，會由維護者提出去識別化摘要並取得專案負責人明確核准；未取得核准時僅保留於私密流程。
- 正式發布前，發布者需在兩個目標市集的管理介面完成無法由版本庫自動設定的隱私連結與其他必要欄位。
- 此功能不取代安全漏洞通報；涉及漏洞或憑證外洩的內容會引導使用既有安全通報管道。
