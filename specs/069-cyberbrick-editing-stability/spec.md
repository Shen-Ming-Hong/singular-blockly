# 功能規格：CyberBrick 中文與編輯穩定性修復

**功能分支**：`069-cyberbrick-editing-stability`

**建立日期**：2026-08-19

**狀態**：Implemented

**輸入**：修復 Blockly 快速操作被舊工作區還原及拖曳中斷、macOS 中文輸入法無法輸入、Windows CyberBrick 終端中文亂碼，以及關閉 Monitor 後通知遮擋上傳資訊等問題。

## 使用者情境與測試 *(必填)*

### 使用者故事 1－快速編輯不再被還原或中斷（優先級：P1）

使用者在任何支援系統快速新增、連接、拖移、刪除或復原積木時，畫面必須保留最新操作，不得因背景檔案事件載回較舊狀態，也不得在拖曳途中被非必要的工作區重載打斷。

**優先此項的理由**：無預警還原會直接造成編輯成果遺失，並使基本拖曳操作失去可信度。

**獨立測試方式**：在 macOS、Windows 與 Linux 快速連續編輯並模擬同一次內部儲存產生多個檔案事件，確認畫面、主檔與備份最終都保留最新版本，且不觸發外部候選載入。

**驗收情境**：

1. **給定** 編輯器剛完成一次內部儲存，**當** 系統收到同一內容的多個建立或變更事件，**則** 所有事件均視為同一內部狀態，不驗證或重新載入工作區。
2. **給定** 使用者快速連續儲存 A、B 兩個版本，**當** A、B 的重複事件交錯到達，**則** 畫面、主檔與備份最終全部保持 B，且 A 不得覆寫 B。
3. **給定** 使用者正在拖移積木，**當** 背景出現與最後內部提交相同的檔案事件，**則** 拖曳不中斷，完成後也不載入舊快照。
4. **給定** 外部工具確實寫入不同內容，**當** 候選通過既有驗證，**則** 系統仍只載入最新世代的有效候選。

---

### 使用者故事 2－Monitor 正常關閉不遮擋上傳資訊（優先級：P1）

使用者開啟 Monitor 後以按鈕關閉、關閉終端頁籤，或立即開始上傳時，這些預期停止流程都必須保持安靜；右下角不得出現異常終止通知或殘留 Monitor 提示，以確保下一次上傳資訊清楚可見。

**優先此項的理由**：通知會遮住上傳進度與結果，使用者無法判斷程式是否成功傳送到裝置。

**獨立測試方式**：連續執行「開啟 Monitor → 關閉 Monitor → 立即上傳」，分別覆蓋按鈕、上傳前自動停止與終端頁籤關閉，確認每次只收到一個正確停止原因、無通知遮擋且上傳進度立即顯示。

**驗收情境**：

1. **給定** Monitor 正在執行，**當** 使用者再次按下 Monitor 按鈕，**則** Monitor 正常停止、按鈕回到未啟用狀態、連線提示立即清除，且不顯示成功或錯誤通知。
2. **給定** Monitor 正在執行，**當** 使用者開始上傳，**則** Monitor 靜默停止，不新增「為上傳暫停」提示，上傳進度成為唯一前景訊息。
3. **給定** 使用者關閉 Monitor 終端頁籤，**當** Monitor 結束，**則** 系統將其視為正常使用者操作，不顯示異常終止通知。
4. **給定** Monitor 程序真正意外失敗或裝置斷線，**當** 系統收到非預期結束，**則** 仍保留錯誤狀態與裝置斷線警告。

---

### 使用者故事 3－macOS 所有文字欄位可正確使用中文輸入法（優先級：P2）

macOS 使用者可在 CyberBrick 的內建字串、函式、參數、網路與裝置設定等所有可輸入文字的積木欄位中使用繁體中文輸入法，組字過程不會被快捷鍵或欄位提交打斷。

**優先此項的理由**：既有修正只涵蓋部分欄位，導致相同輸入行為在不同積木間不一致。

**獨立測試方式**：以 macOS 繁體中文輸入法逐一操作規格列出的所有文字欄位，確認組字、候選選字、送出、儲存與重新載入均保留完整文字。

**驗收情境**：

1. **給定** 使用者正在任一文字欄位進行中文組字，**當** 輸入法送出 composition 或等價的處理中鍵盤事件，**則** 編輯器與全域快捷鍵不提前處理該事件。
2. **給定** 使用者完成中文組字，**當** 欄位提交、工作區儲存並重新載入，**則** 中文內容完整保留且不出現重複、漏字或意外快捷鍵動作。
3. **給定** 欄位原本具有識別字或格式驗證限制，**當** 本功能套用中文輸入相容處理，**則** 既有驗證規則、序列化與程式產生行為不變。

---

### 使用者故事 4－Windows CyberBrick 終端完整顯示 UTF-8 中文（優先級：P2）

Windows 使用者透過 CyberBrick 的一般序列監看與互動式終端查看或輸入中文時，文字必須完整顯示，不因作業系統預設編碼或資料分段而出現亂碼與替代字元。

**優先此項的理由**：終端亂碼會使教學輸出、診斷訊息與互動式操作無法閱讀。

**獨立測試方式**：在 Windows 分別使用 CyberBrick 的一般序列監看與互動式終端，輸出及輸入「中文測試」，並將 UTF-8 位元資料刻意分割成多段，確認輸出完全相同且不含替代字元。

**驗收情境**：

1. **給定** 裝置輸出 UTF-8 中文，**當** 單一中文字元的位元資料跨多個輸出片段到達，**則** 終端仍輸出完整字元，不產生 `�`。
2. **給定** Windows 使用非 UTF-8 系統地區設定，**當** CyberBrick 監看程序啟動，**則** 中文輸出仍以 UTF-8 傳遞與顯示。
3. **給定** CyberBrick 使用一般序列監看或互動式終端，**當** 使用者查看輸出或進行 REPL 中文輸入，**則** 兩條路徑都遵守相同 UTF-8 契約。
4. **給定** Arduino Monitor 收到跨片段 UTF-8 文字，**當** 終端顯示資料，**則** 同樣不得產生替代字元。

### 邊界情境

- 同一次內部原子寫入產生任意數量、任意順序的建立與變更事件時，符合最後內部提交內容的事件都必須冪等忽略。
- 連續內部提交之間若夾入真正不同內容的外部修改，只能將不同內容視為候選，且較舊世代不得覆寫較新世代。
- 內部刪除、復原、候選提交或隔離流程產生重複刪除／建立事件時，不得形成監看迴圈。
- 使用者在拖曳結束前收到真正外部候選時，既有延後載入保護仍必須保留；本功能不得使外部候選在拖曳中套用。
- 中文組字事件可由 composition 狀態、`Process` 鍵值或鍵碼 229 表示，三種形式都必須視為尚未完成的輸入。
- 中文輸入相容不得繞過 SSID、密碼、伺服器、變數名稱或函式名稱原有的驗證器。
- UTF-8 字元可能跨任意輸出片段，標準輸出與錯誤輸出必須各自保留解碼狀態，並在程序結束時輸出剩餘完整資料。
- Monitor 預期停止與程序結束事件可能幾乎同時發生；同一生命週期仍只能回報一次停止原因。
- 使用者正常停止後緊接著開始新的 Monitor 或上傳生命週期時，上一輪的延遲事件不得改變新一輪按鈕或提示狀態。

## 需求 *(必填)*

### 功能需求

- **FR-001**：系統必須持續記錄 `blockly/main.json` 最後一次內部提交的精確預期狀態，包含「存在且內容相同」或「不存在」。
- **FR-002**：與最後內部提交狀態相符的每一個重複檔案事件都必須冪等忽略，不得因處理第一個事件而失去後續事件的內部身分。
- **FR-003**：編輯器儲存、有效候選提交、復原、內部刪除及初始化成功都必須建立或更新精確的預期主檔狀態。
- **FR-004**：只有磁碟內容確實不同於最後內部提交狀態時，系統才能啟動外部候選驗證與正式工作區載入。
- **FR-005**：快速連續提交與交錯事件中，畫面、主檔及備份必須收斂到最後成功提交版本；較舊版本或世代不得覆寫較新版本。
- **FR-006**：既有外部候選驗證、隔離、復原、備份、世代控制、空狀態保護及拖曳延後載入行為必須保留。
- **FR-007**：所有使用文字輸入欄位的內建與自訂積木都必須採用相同的中文輸入法相容行為。
- **FR-008**：中文 composition、`Process` 及鍵碼 229 處理期間不得觸發欄位提交、Blockly 快捷鍵或編輯器全域快捷鍵。
- **FR-009**：中文輸入相容處理不得改變既有欄位驗證器、識別字限制、序列化格式或程式碼產生規則。
- **FR-010**：中文輸入稽核至少必須涵蓋 `text`、`arduino_function`、`servo_setup`、`encoder_setup`、`encoder_pid_setup`、`esp32_wifi_connect`、`esp32_mqtt_setup`、`esp32_mqtt_connect`、`threshold_function_setup`、`txt_process` 及函式參數欄位。
- **FR-011**：CyberBrick 的一般序列監看與互動式終端程序必須在 Windows 明確使用 UTF-8 輸入輸出契約，同時保留其他既有環境設定與不經命令殼層執行的安全特性。
- **FR-012**：Monitor 的標準輸出與錯誤輸出必須各自以串流方式解碼 UTF-8，正確處理跨片段字元及程序結束時的剩餘資料。
- **FR-013**：Arduino Monitor 必須套用相同的跨片段 UTF-8 解碼保護。
- **FR-014**：每次 Monitor 生命週期必須只回報一次停止原因，原因限於手動停止、上傳前停止、使用者關閉終端或裝置／程序意外中斷。
- **FR-015**：手動停止、上傳前停止及使用者關閉終端必須視為預期且成功的停止，不得觸發 VS Code 異常終止通知。
- **FR-016**：真正未預期的非成功退出必須保留錯誤狀態與裝置斷線警告。
- **FR-017**：Monitor service 的停止回報必須是停止訊息的唯一來源，其他訊息處理層不得再額外發送重複停止訊息。
- **FR-018**：手動停止必須立即清除仍顯示的 Monitor 連線提示，靜默更新按鈕及日誌；不得顯示成功通知。
- **FR-019**：上傳前停止不得新增 Monitor 暫停提示，且不得延遲或遮擋隨後的上傳進度資訊。
- **FR-020**：本功能不得新增使用者設定、命令、翻譯字串或工作區 JSON 欄位，也不得回退必要主程式停用保護。

### 關鍵實體

- **預期主檔狀態**：最後一次可信內部操作對 `main.json` 的精確期望，包含存在狀態與內容身分，用於區分內部重複事件與真正外部修改。
- **外部候選世代**：真正不同於預期主檔狀態的外部內容版本；只有最新世代可完成驗證及正式載入。
- **文字輸入欄位**：可接收鍵盤與輸入法組字的 Blockly 欄位，保留各欄位原有驗證及序列化契約。
- **UTF-8 串流**：標準輸出或錯誤輸出的獨立位元資料序列，可在任意片段邊界切割多位元字元。
- **Monitor 生命週期**：從啟動到停止的一次連線工作階段，具有最多一個最終停止原因與預期／非預期結束狀態。

## 成功標準 *(必填)*

### 可量測成果

- **SC-001**：單次內部儲存後收到至少五個重複建立／變更事件時，外部驗證與正式載入呼叫數都保持為零。
- **SC-002**：快速連續提交 A、B 並交錯重複事件的所有自動測試中，畫面、主檔與備份 100% 收斂到 B，且真正外部候選仍只載入最新世代。
- **SC-003**：macOS 繁體中文輸入法在規格列出的全部文字欄位完成組字、選字、儲存與重新載入，零漏字、零重複字及零非預期快捷鍵。
- **SC-004**：將「中文測試」的 UTF-8 位元資料在每個可能的字元內邊界分割後，CyberBrick 兩種 Monitor 與 Arduino Monitor 的輸出都與原字串完全相同且不含 `�`。
- **SC-005**：手動按鈕停止、上傳前停止及終端頁籤關閉的自動測試各只回報一個正確停止原因，全部視為成功結束且不觸發資訊、警告或錯誤通知。
- **SC-006**：連續執行至少十次「開啟 Monitor → 關閉 Monitor → 立即上傳」後，右下角零殘留 Monitor 提示，上傳進度與結果每次都可立即完整顯示。
- **SC-007**：真正非預期程序失敗的回歸測試 100% 保留非成功狀態與裝置斷線警告。
- **SC-008**：macOS、Windows、Linux 的快速新增、連接、拖移、刪除與復原手動矩陣中，零操作被舊快照還原，零拖曳遭內部重複事件中斷。
- **SC-009**：編譯、Lint、完整單元測試、整合測試、專案 Skill 契約檢查及 15 語系驗證全部通過。

## 假設

- CyberBrick 裝置及互動式終端輸出契約為 UTF-8；Big5／CP950 自動偵測不在本次範圍。
- 手動停止、上傳前停止與使用者關閉終端屬正常控制流程；只有真正錯誤需要主動提示。
- 既有工作區候選驗證與世代控制仍是外部修改的權威流程，本功能只修正內部事件的冪等辨識。
- WebView 互動的自動契約測試搭配規格列出的平台手動矩陣，可滿足本次 UI 驗收。
- 現有文字欄位驗證器仍決定欄位是否接受中文；本功能只確保輸入法組字不被過早處理。

## 範圍外

- 新增 Big5、CP950 或其他裝置編碼的自動偵測與轉碼。
- 放寬函式名稱、變數名稱、網路設定或其他文字欄位的既有驗證規則。
- 變更外部 `main.json` 的驗證、隔離、復原、備份格式或工作區文件 schema。
- 新增 Monitor 設定、通知偏好、命令、翻譯字串或使用者可調整的停止政策。
- 修改必要主程式停用保護及其載入、修復與產生器契約。
