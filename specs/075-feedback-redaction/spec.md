## 使用情境與驗收

### 使用情境一：貼上傳錯誤也能送出（P1）

學生在 Windows 上傳失敗，把終端機的錯誤整段貼進「說明」：裡面有 `C:\Users\<姓名>\...\blink.ino:12:5`、`COM3` 與一個 IP。按「檢視要送出的內容」後，預覽中路徑變成 `[path]:12:5`、序列埠變成 `[serial port]`、IP 變成 `[IP]`，其他錯誤文字保留，確認後成功送出。

**Independent Test**：在回饋表單貼上含上述內容的文字，預覽與送到服務的內容都只含佔位文字，且送出成功。

**Acceptance Scenarios**：

1. **Given** 說明含 Windows 路徑（資料夾名稱含空白）、COM 埠與 IPv4，**When** 檢視，**Then** 預覽中只剩 `[path]`、`[serial port]`、`[IP]`，行號與錯誤文字保留。
2. **Given** 說明含 macOS／Linux 路徑、`/dev/tty*`、IPv6 或 UUID，**When** 檢視，**Then** 同樣換成對應佔位文字。
3. **Given** 說明含 Arduino／MicroPython 程式片段、Traceback 或 `npm ERR!`，**When** 檢視，**Then** 原文保留並可送出。
4. **Given** 說明含一般網址（例如 GitHub issue 連結），**When** 檢視，**Then** 網址保留；網址裡的 IP 仍換成 `[IP]`。

### 使用情境二：憑證仍被擋下（P1）

使用者不小心把含 `GITHUB_TOKEN=...` 或私密金鑰的設定檔貼進回饋。系統拒絕產生預覽，提示「偵測到密碼、權杖或私密金鑰等憑證，請移除後再檢視」。

**Acceptance Scenarios**：

1. **Given** 任一文字欄位含憑證，**When** 檢視或送出，**Then** 不產生預覽、不建立匿名憑證、不呼叫服務，並顯示憑證專用的錯誤訊息。
2. **Given** 繞過擴充套件直接呼叫服務並帶憑證，**When** 服務驗證，**Then** 回 `sensitive_content`，不寫入資料庫或同步佇列。

### 使用情境三：補充訊息與入口網站一致（P2）

回報者在「我的回饋」或私人備援連結補充一則含路徑的訊息。送出前就遮蔽，服務存下的內容與畫面上顯示的一致，重試不會被當成不同訊息。

**Acceptance Scenarios**：

1. **Given** 補充訊息含 COM 埠與路徑，**When** 送出，**Then** 服務收到並儲存遮蔽後的內容。
2. **Given** 入口網站送出含路徑的訊息，**When** 服務回傳內容，**Then** 與瀏覽器送出的遮蔽內容完全相同。

### 使用情境四：公開摘要再遮一次（P3）

負責人核准公開摘要時，摘要裡若仍留有路徑、埠號或 IP，建立公開 Issue 前再遮一次。

### Edge Cases

- 遮蔽後文字變長而超過欄位上限：擴充套件回「輸入無效」，服務回 `invalid_field`／`invalid_message`，不寫入資料庫。
- 已遮蔽的文字再遮一次結果不變（佔位文字本身不會被當成路徑或 IP）。
- 產品名稱裡的斜線（`Arduino/MicroPython`、`upload/download`、`light/dark`）不被當成路徑。
- `12:30:45` 這類時間、MAC 位址不會被當成 IPv6。
- 路徑最後一段後面接著含空白的文字（例如 `C:\Users\名 姓` 沒有結尾反斜線）時，只遮到第一個空白之前；有下一層資料夾時整段遮蔽。
- 四段數字的版本號（例如 `1.2.3.4`）會被當成 IP 遮蔽；接受此誤判。
- 舊版擴充套件仍在本機拒收路徑等內容；新規則要等新版 VSIX 才對它們生效。

## Requirements

### Functional Requirements

- **FR-001**：系統 MUST 在回報者撰寫的標題、說明、重現步驟、預期結果與補充訊息中，偵測到憑證時整段拒絕，並回固定錯誤碼 `sensitive_content`。
- **FR-002**：系統 MUST 把本機路徑（Windows 磁碟與 UNC、Unix 絕對路徑、`./`、`../`、`~/` 與帶副檔名的相對路徑）換成 `[path]`；序列埠（`COMn`、`/dev/tty*`、`/dev/cu.*`）換成 `[serial port]`；IPv4 與 IPv6 換成 `[IP]`；UUID 換成 `[ID]`。
- **FR-003**：系統 MUST NOT 因程式碼、Traceback、終端機輸出或網址而拒收；一般網址保留原文。
- **FR-004**：擴充套件 MUST 在預覽前完成遮蔽，預覽、確認比對與實際送出使用同一份遮蔽結果。
- **FR-005**：服務 MUST 以同一套規則再驗證與遮蔽，且在遮蔽後重新檢查長度上限。
- **FR-006**：入口網站送出補充訊息前 MUST 套用同一套規則，讓伺服器回傳內容與送出內容一致。
- **FR-007**：核准公開摘要建立公開 Issue 前 MUST 再遮蔽一次。
- **FR-008**：15 語系的表單警語與憑證錯誤訊息 MUST 說明新行為；隱私政策 MUST 說明遮蔽與拒收。

### Key Entities

- **遮蔽規則**：一份共用定義，供擴充套件、服務與入口網站使用；分「拒收」與「替換」兩組。
- **佔位文字**：`[path]`、`[serial port]`、`[IP]`、`[ID]`。

## Success Criteria

- **SC-001**：含路徑、COM 埠與 IP 的上傳錯誤，100% 可以送出，且送出內容中不含原始路徑、埠號或 IP。
- **SC-002**：含憑證的內容 100% 被擋下，且不建立任何紀錄。
- **SC-003**：同一段文字在擴充套件、服務與入口網站的遮蔽結果完全相同。
- **SC-004**：Ray 能把自己的上傳錯誤原文貼進回饋並送出（新版 VSIX 發布後）。

## Assumptions

- 回饋內容只存在私人工作區，維護者不需要真實路徑或埠號就能判斷問題；行號與錯誤本文保留。
- 姓名、電子郵件等一般文字仍靠表單警語提醒，不做自動偵測（與 070 相同）。
- Worker 無資料表變更，不需要 migration。
