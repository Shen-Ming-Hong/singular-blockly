# 功能規格：Agent Skills 取代 MCP

**功能分支**：`codex/066-agent-skills-mcp-retirement`

**建立日期**：2026-08-12

**狀態**：草稿

**輸入**：以專案內 Agent Skills 取代過時的 MCP 整合，讓支援的 AI 不需使用者安裝系統 Node.js，即可理解、建立及安全修改可由 Singular Blockly 載入的積木工作區。

## Clarifications

### Session 2026-08-12

- Q: 當使用者修改了 Singular Blockly 管理的 Skill 檔案，之後擴充套件需要更新該檔案時，應採取哪種處理方式？ → A: 備份使用者版本後，以新版受管理檔案覆寫。
- Q: 連續出現多個無效 AI 工作區時，應保留多少份隔離內容？ → A: `main.invalid.json` 保留最新內容，另保留最近 5 份帶時間的歷史備份。
- Q: 外部 `main.json` 變更送交 Blockly 驗證後，最長應等待多久才判定逾時並啟動隔離與恢復？ → A: 10 秒。
- Q: 使用者第一次同意建立專案 Skills 後，未來受管理檔案有新版時是否需要再次確認？ → A: 專案啟動時即自動置入並更新 Skills，初次與後續更新都不需使用者確認。
- Q: 如果 Skills 自動建立或更新失敗，是否要讓一般使用者看到通知？ → A: 不通知使用者；記錄診斷，並在可安全寫入時提供 AI 可讀狀態。
- 使用者補充規則：所有由擴充套件建立或管理的 Skill 內容一律使用英文。

## 使用者情境與測試 *(必填)*

### 使用者故事 1：不安裝額外執行環境即可啟用 AI 專案指引（優先級：P1）

身為教師、學生或一般使用者，我希望啟動 Singular Blockly 專案後，AI 自動取得所需的專案 Skills，不必安裝系統 Node.js、啟動 MCP server、回應設定確認或了解隱藏的 AI 設定檔。

**優先原因**：移除額外安裝與設定門檻是本功能的核心價值；若仍需要 Node.js 或 MCP，便未解決目前最主要的使用障礙。

**獨立測試**：在沒有系統 Node.js 與任何 Singular Blockly MCP 設定的新環境中建立或開啟專案，確認 Skills 於專案啟動時自動建立或更新，過程不要求使用者確認，且 Blockly 編輯器維持正常使用。

**驗收情境**：

1. **假設**使用者第一次啟動可寫入的 Singular Blockly 專案，**當**系統辨識專案，**則**自動置入可納入版本控制的正式 Skill 與支援代理相容入口，不顯示確認或成功通知。
2. **假設**專案已有舊版受管理 Skills，**當**使用者以新版擴充套件啟動專案，**則**受管理內容自動更新，不要求版本更新確認。
3. **假設**Skills 無法完整建立或更新，**當**使用者繼續使用專案，**則**不會留下被視為成功的部分更新或顯示一般通知，診斷會被記錄並盡可能提供 AI 可讀狀態，且 Blockly 編輯、儲存與程式產生功能不受影響。
4. **假設**電腦未安裝可供使用者呼叫的 Node.js，**當**使用者啟用並使用專案 Skills，**則**整個使用流程仍可完成，且不會顯示 Node.js 或 MCP 安裝警告。

### 使用者故事 2：AI 能理解並產生合法積木工作區（優先級：P1）

身為使用 AI 協助設計積木程式的使用者，我希望 VS Code/Codex 與 Claude Code 能從專案 Skill 理解目前工作區、可用積木與資料限制，並建立可由 Singular Blockly 正常載入及繼續編輯的內容。

**優先原因**：Skills 不只要取代說明文件，還必須使 AI 的實際輸出符合目前積木定義；否則移除 MCP 後無法維持原本的 AI 輔助價值。

**獨立測試**：分別以明列支援的 AI 代理讀取代表性 Arduino、CyberBrick MicroPython 與 TXT Controller 專案，要求其解釋現有工作區並完成新增、修改及刪除積木，確認結果可載入、可再儲存並產生對應程式。

**驗收情境**：

1. **假設**專案含有有效的 `main.json`，**當**支援的 AI 讀取專案 Skill，**則**能找到工作區檔案、辨識開發板、積木結構及適用限制。
2. **假設**使用者要求 AI 新增或修改支援的積木流程，**當**AI 寫回候選工作區，**則**內容符合目前編輯器的積木定義、連線、欄位、變數及序列化規則。
3. **假設**AI 完成有效修改，**當**使用者開啟或保持開啟 Blockly 編輯器，**則**修改可安全載入、繼續視覺化編輯並再次儲存。
4. **假設**有效工作區分別使用三種支援的程式產生流程，**當**產生程式碼，**則**輸出分別位於 Arduino 的 `src/main.cpp`、CyberBrick 的 `src/rc_main.py` 與 TXT Controller 的 `src/main.py`。

### 使用者故事 3：無效 AI 修改不會破壞專案（優先級：P2）

身為讓 AI 直接修改工作區的使用者，我希望任何不完整、格式錯誤或不符合積木規則的內容都不會取代目前可用的專案，並且能看到可採取行動的問題說明。

**優先原因**：AI 寫入屬於外部檔案變更；若沒有可靠驗證與回復機制，單次錯誤便可能造成積木遺失或使編輯器無法開啟。

**獨立測試**：依序寫入截斷 JSON、未知積木、非法連線、錯誤欄位、缺少動態狀態與超時候選資料，確認每次都保留最後有效工作區、隔離無效內容並提供診斷。

**驗收情境**：

1. **假設**AI 寫入無法解析的候選工作區，**當**系統偵測變更，**則**最新無效內容會被隔離為 `main.invalid.json` 並加入帶時間的有限歷史，`main.json` 會恢復為最後有效版本。
2. **假設**候選資料可解析但含有未知積木、非法連線或無法還原的狀態，**當**依目前編輯器規則驗證，**則**候選資料不會載入正式工作區，且使用者會收到可定位問題的診斷。
3. **假設**候選工作區送交驗證後未在 10 秒內取得結果或編輯器暫時不可用，**當**系統判定驗證逾時，**則**採取與其他無效候選相同的保護處理，不會繼續等待或覆寫有效資料。
4. **假設**AI 寫入的是有效候選資料，**當**驗證完成，**則**正式工作區載入該版本並將其視為新的最後有效狀態。

### 使用者故事 4：Skills 可更新且不覆蓋使用者內容（優先級：P3）

身為持續更新 Singular Blockly 的使用者，我希望擴充套件能讓專案 Skills 跟上最新積木與格式，同時保留我在專案中加入的筆記、規則及自訂 Skill 檔案。

**優先原因**：積木定義會隨版本演進；完全不更新會讓 AI 知識過時，而粗暴覆寫整個目錄則會破壞使用者的專案知識。

**獨立測試**：建立含舊版受管理檔案、已修改專案筆記及額外自訂檔案的專案後升級擴充套件，確認受管理內容更新、相容入口同步，使用者內容逐位元保持不變。

**驗收情境**：

1. **假設**專案使用舊版受管理 Skill 檔案，**當**使用者以新版擴充套件啟動專案，**則**系統自動更新可辨識的受管理檔案，且更新後契約符合目前積木能力。
2. **假設**使用者已編輯指定的專案筆記或加入自訂檔案，**當**受管理 Skills 更新，**則**這些使用者內容不會被刪除、重命名或覆寫。
3. **假設**可確認為受管理的檔案已被使用者修改，**當**系統準備更新，**則**先完整備份使用者版本，再以新版受管理檔案覆寫，並在 AI 可讀狀態中記錄備份位置，不顯示一般通知。
4. **假設**更新期間無法寫入所有必要檔案，**當**更新失敗，**則**原本可用的 Skill 組合保持完整，不顯示一般通知，並將失敗寫入診斷及可安全建立的 AI 可讀狀態。

### 邊界情況

- 專案為唯讀、工作區資料夾不存在或使用者沒有建立隱藏目錄的權限時，不得留下半套 Skills，也不得阻止一般編輯。
- 專案已存在同名但無法確認為 Singular Blockly 管理的 Skill 時，不得直接覆寫；必須保留原內容，將衝突寫入診斷及可安全建立的 AI 可讀狀態，不顯示一般通知。
- 使用者已修改可確認為受管理的檔案時，系統必須先保存逐位元相同的使用者版本，再覆寫受管理檔案；備份失敗時不得繼續更新。
- 專案為唯讀或無法安全寫入 AI 可讀狀態時，系統只能寫入擴充套件診斷紀錄，不得為了產生狀態而放寬路徑或權限限制。
- AI 寫入空物件、空工作區或刪除 `main.json` 時，既有空狀態保護仍須避免有效工作區被意外清空。
- AI 與 Blockly 編輯器幾乎同時寫入 `main.json` 時，只有完整通過驗證的版本能成為最後有效狀態，且不得形成持續監看迴圈。
- 候選工作區含有已移除、隱藏、開發板不適用、孤立或動態積木時，必須依目前編輯器的同一套規則判定，而非只檢查 JSON 語法。
- 大型工作區送交驗證後超過 10 秒、編輯器關閉或驗證通道中斷時，必須保留最後有效版本並提供非破壞性的重試方式。
- 隔離歷史已達 5 份時，新增失敗候選必須先保留為最新隔離內容，再移除最舊的帶時間歷史；不得誤刪 `main.invalid.json`、`main.json` 或其他專案檔案。
- `.agents/skills` 成功更新但代理相容入口更新失敗時，整次更新不得被視為成功。
- 使用者在版本控制中回復較舊 Skill 版本時，下次啟動專案會再次自動更新，但仍須遵守備份與使用者內容保護規則。

## 需求 *(必填)*

### 功能需求

- **FR-001**：一般使用者必須能在未安裝系統 Node.js、未設定 MCP 且未啟動外部 server 的環境中使用 Singular Blockly 與本功能提供的 AI 專案指引。
- **FR-002**：系統必須在每次 Singular Blockly 專案啟動時自動檢查並建立或更新受管理 Skills；初次置入與一般版本更新都不得要求使用者確認，也不得顯示成功通知。
- **FR-003**：若無法完整建立或更新 Skills，系統不得留下被視為成功的部分受管理內容，不得顯示一般使用者通知，且一般 Blockly 功能必須維持可用；失敗必須寫入擴充套件診斷，並在專案可安全寫入時提供 AI 可讀狀態。
- **FR-004**：系統必須自動在 `.agents/skills/singular-blockly/` 建立唯一正式的專案 Skill 契約，並使其可由版本控制追蹤。
- **FR-005**：系統必須在 `.claude/skills/singular-blockly/SKILL.md` 建立精簡相容入口，引導 Claude Code 使用正式契約，不得維護另一份可能分歧的完整契約或使用符號連結。
- **FR-006**：正式 Skill 必須說明工作區檔案位置、支援的開發板、合法資料結構、可用積木、欄位與連線限制、修改流程、驗證結果及錯誤復原方式。
- **FR-007**：正式 Skill 契約必須由目前實際可用的積木與工作區規則產生；每個可供使用者建立的積木類型都必須有對應契約，且不得把已移除或不可用積木當成可建立內容。
- **FR-008**：VS Code/Codex 與 Claude Code 必須能從各自支援的專案入口找到相同的正式 Skill 契約，並取得等價的工作區指引。
- **FR-009**：候選 `main.json` 在影響正式視覺工作區前，必須使用與目前 Blockly 編輯器相同的積木定義及還原規則完成驗證；僅通過 JSON 語法檢查不得視為有效。
- **FR-010**：通過驗證的外部工作區變更必須能載入目前編輯器、再次儲存，並成為新的最後有效工作區版本。
- **FR-011**：候選工作區送交 Blockly 驗證後，若未在 10 秒內取得結果即視為逾時；未通過驗證或驗證逾時的最新候選內容必須保存為 `main.invalid.json` 供診斷，另保留最近 5 份帶時間的隔離歷史，並以最後有效內容恢復 `main.json`；新增第 6 份歷史時只移除最舊歷史，無效內容不得載入正式工作區。
- **FR-012**：系統必須針對無效候選顯示不含候選內容的在地化警告，說明問題類型、隔離檔專案相對位置及可查看的診斷詳情；此工作區資料警告不屬於 Skills 建立／更新通知，且錯誤處理不得靜默遺失候選資料或最後有效資料。
- **FR-013**：現有防止空白或中間狀態覆寫有效工作區的保護行為必須維持，並適用於 AI 或其他外部檔案寫入。
- **FR-014**：有效工作區必須維持 Arduino、CyberBrick MicroPython 與 TXT Controller 的程式產生能力，輸出位置分別為 `src/main.cpp`、`src/rc_main.py` 與 `src/main.py`。
- **FR-015**：系統必須使用可驗證版本與受管理檔案清單辨識自動更新範圍，只能更新確認由 Singular Blockly 管理的內容；若受管理內容已被使用者修改，必須先建立逐位元相同的備份、在 AI 可讀狀態中記錄位置，再以新版受管理內容覆寫。
- **FR-016**：自動更新必須保留指定的專案筆記、使用者新增檔案及無法確認為受管理的內容，不得以重建整個 Skills 目錄的方式覆寫。
- **FR-017**：Skills 建立或更新必須具備整體一致性；任一必要受管理檔案失敗時，不得留下被視為成功的新舊混合狀態。
- **FR-018**：同一正式版本必須移除使用者端 MCP server、MCP 工具與資源、Node.js 路徑偵測、安裝警告、命令、設定、診斷及過時說明，不提供過渡模式或相容 server。
- **FR-019**：移除使用者端 MCP 與 Node.js 需求不得移除貢獻者進行擴充套件建置、測試與封裝所需的開發工具鏈。
- **FR-020**：擴充套件最低支援版本必須提高至 VS Code 1.109，並以該版本正式提供的專案 Agent Skills 能力作為支援基準。
- **FR-021**：既有有效 Blockly 專案在升級後必須維持可開啟、編輯、儲存與產生程式碼，不得要求轉換既有 `main.json` 才能繼續使用。
- **FR-022**：一般使用者不得看到無法執行的 MCP 命令、MCP 狀態、系統 Node.js 設定提示或正常 Skills 建立與更新通知；受管理設定應由支援的 AI 自動發現。
- **FR-023**：擴充套件建立或管理的所有 Skill 人類可讀內容必須使用英文，包括正式 `SKILL.md`、references、契約說明、受管理 manifest、AI 可讀狀態與代理相容入口；不得產生繁體中文或其他語言版本。
- **FR-024**：AI 可讀狀態與診斷不得包含憑證、完整工作區內容、使用者自訂檔案內容或專案外部絕對路徑，只能記錄狀態、受管理檔案識別、專案內相對路徑及可採取的恢復動作。

### 關鍵實體

- **正式專案 Skill 契約**：專案內提供給支援 AI 的唯一權威指引，包含啟用描述、工作區格式、積木契約、修改流程與安全限制。
- **代理相容入口**：特定 AI 所使用的精簡入口，只負責定位正式契約，不複製其完整規則。
- **受管理檔案清單**：記錄 Singular Blockly 可安全建立或更新的 Skill 檔案、版本與內容識別資訊，並與使用者內容區隔。
- **候選工作區**：外部寫入但尚未獲准載入正式工作區的 `main.json` 內容，必須先接受完整積木還原驗證。
- **最後有效工作區**：最近一次通過驗證且可由編輯器正常載入的工作區內容，是驗證失敗時的恢復來源。
- **隔離工作區**：未通過驗證的候選內容；`main.invalid.json` 保存最新內容，另以帶時間的檔案保存最近 5 份歷史，所有隔離內容都不參與正式載入。
- **AI 可讀狀態**：供支援代理判斷 Skills 版本、建立或更新結果、備份位置與恢復動作的英文受管理資料，不包含敏感資料或使用者檔案內容。

### 範圍界線

- 本功能不提供新的聊天介面、AI 模型、帳號登入、雲端代理服務或通用程式設計助理。
- 本功能首版只明列支援 VS Code/Codex 與 Claude Code；其他能讀取正式 Skill 的代理可自行使用，但不列入相容性承諾。
- 本功能不將任意 Arduino C++ 或 Python 原始碼自動逆向轉換成積木工作區。
- 本功能不改變 `main.json` 對外工作區格式；重點是提供正確契約並在外部修改載入前驗證。
- 本功能不移除專案貢獻者的 Node.js 開發工具鏈，也不改變 PlatformIO、mpremote 或硬體上傳流程。
- 本功能不保留或重新包裝原 MCP server，不提供 MCP 到 Skill 的雙軌過渡期。
- 本功能不新增要求一般使用者管理、確認或理解 Skills 的設定介面；Skills 是專案內供 AI 自動發現的受管理能力。
- 本功能不自動提交使用者專案中的 Skills；是否提交由使用者與其版本控制流程決定。

## 成功標準 *(必填)*

### 可衡量成果

- **SC-001**：在沒有系統 Node.js 與 MCP 設定的驗收環境中，新專案及既有專案都能於啟動後 30 秒內自動完成 Skills 建立或更新，成功率為 100%，要求使用者確認的次數為零。

## 假設

- Singular Blockly 專案啟動是新建與既有專案的共同生命週期，因此作為 Skill 自動建立與更新檢查點，而非等待後續的編輯器事件。
- 專案根目錄在啟動時通常可寫入；唯讀或權限不足情況依非破壞性失敗流程處理。
- `.agents/skills/singular-blockly/` 是正式契約位置，`.claude/skills/singular-blockly/SKILL.md` 是不使用符號連結的精簡相容入口。
- Skill 檔案應可納入版本控制，但擴充套件不代替使用者執行版本控制提交。
- 使用者端不再需要 Node.js；Node.js 仍是 Singular Blockly 開發、測試與封裝工具鏈的一部分。
- 支援的工作區主檔名維持 `main.json`，三種現有程式產生流程與輸出位置保持不變。
- 無效工作區的隔離保留上限固定為最新檔案加 5 份歷史，不提供使用者自訂數量設定。
- 候選工作區驗證上限固定為 10 秒，不新增使用者設定；需要更長時間的工作區會依逾時保護流程處理。
- Skills 與積木契約會隨擴充套件版本更新；使用者筆記與未列入受管理清單的檔案永久視為使用者內容，使用者對受管理檔案的修改則在更新覆寫前完整備份。
- 所有受管理 Skill 內容固定使用英文，不依 VS Code 顯示語言或 Singular Blockly 介面語言產生翻譯版本。
- 本功能直接取代舊 MCP 整合，不提供過渡期、相容 server 或自動轉換既有外部 MCP client 設定。

## 相依條件

- VS Code 1.109 或更新版本能依正式支援方式發現專案 Agent Skills。
- Claude Code 能從專案內 `.claude/skills/` 發現相容入口並依其指引讀取正式契約。
- Singular Blockly 現有積木定義、工具箱、工作區序列化與三種程式產生流程可作為契約與驗證的權威來源。
- 現有檔案監看與工作區空狀態保護可作為外部候選資料驗證流程的整合邊界。
